# 예약 서버 붙이기 (10분)

`Code.gs` 를 구글 스프레드시트에 붙이면 예약 접수가 돌아간다. 서버를 따로 두지 않고,
**선생님이 시트에서 상태를 바꾸는 게 곧 승인**이다.

## 1. 시트 만들기

1. 학교 구글 계정으로 [스프레드시트](https://sheets.new) 를 새로 만든다.
   이름은 `방 예약 장부` 정도.
2. **확장 프로그램 → Apps Script** 를 연다.
3. 편집기의 `Code.gs` 내용을 지우고 이 폴더의 `Code.gs` 를 통째로 붙여넣는다.
4. 맨 위 `NOTIFY_EMAIL` 에 담당 선생님 주소를 적는다.

   ```js
   var NOTIFY_EMAIL = "seonsaeng@school.kr";
   ```

   > 비워두면 신청이 들어와도 **아무도 모른다.** 승인이 있어야 확정이므로
   > 이 줄이 비면 시스템이 안 돈다.

5. 저장하고 시트로 돌아가 새로고침하면 위쪽에 **방 예약** 메뉴가 생긴다.
   **방 예약 → 시트 준비** 를 한 번 누른다. `예약` 시트와 상태 드롭다운이 만들어진다.

## 2. 웹앱으로 배포

Apps Script 편집기에서 **배포 → 새 배포**:

| | |
|---|---|
| 유형 | **웹 앱** |
| 실행 계정 | **나** ← 중요 |
| 액세스 권한 | **모든 사용자** |

*실행 계정을 '나' 로 두는 게 핵심이다.* 그래야 학생 계정에 시트 권한을 하나도
주지 않고도 신청이 기록된다. 학생은 시트 주소를 알아도 열지 못한다.

처음 배포할 때 권한 승인 화면이 뜬다. "안전하지 않음" 경고가 나오면 본인이 만든
스크립트이므로 그대로 진행하면 된다.

배포가 끝나면 이런 주소가 나온다:

```
https://script.google.com/macros/s/AKfycb…/exec
```

## 3. 사이트에 연결

`src/config.js` 의 `RESERVATION_ENDPOINT` 에 위 주소를 붙여넣는다.

```js
export const RESERVATION_ENDPOINT = "https://script.google.com/macros/s/AKfycb…/exec";
```

`npm run build` 하고 푸시하면 끝이다. 비어 있는 동안에는 예약 창이 열리되
"아직 연결되지 않았습니다" 가 뜨고 신청 버튼이 잠긴다.

## 3.5 상태 바뀔 때 신청자에게 알리기 (트리거 하나 더)

승인만이 아니라 **되돌리는 경우가 더 중요하다.** "승인됐다" 고 알고 있는 사람에게
취소·반려를 안 알리면 그 시간에 그냥 온다.

Apps Script 편집기 왼쪽 **트리거(⏰)** → **트리거 추가**:

| | |
|---|---|
| 실행할 함수 | `onStatusEdit` |
| 이벤트 소스 | 스프레드시트에서 |
| 이벤트 유형 | **수정 시** |

> `onEdit` 라는 이름의 단순 트리거는 메일을 못 보낸다. 반드시 이렇게 **설치형**으로
> 걸어야 한다.

신청자의 `연락` 칸이 **이메일일 때만** 보낸다. 전화번호로 문자를 보내려면 외부 유료
API 와 발신번호 사전등록(법적 의무)이 필요해서 학교 차원 승인 없이는 못 붙인다.

## 4. 확인

1. 사이트에서 예약 가능한 방(예: 하늬콜로키움)을 클릭 → **예약하기**
2. 날짜와 교시를 고르고 이름을 적어 신청
3. 시트에 줄이 생기고 `상태` 가 `대기` 인지 확인
4. 담당 선생님께 메일이 갔는지 확인
5. 시트에서 `상태` 를 `승인` 으로 바꾼다
6. 예약 창을 다시 열면 그 교시가 빗금으로 잠겨 있어야 한다
   (조회 응답을 60초 묶어두므로 바로 안 바뀌면 1분 뒤에 본다)

## 알아둘 것

**행을 지우지 마세요.** 취소도 `상태` 를 `취소` 로 바꾸는 것으로 한다. 지우면
**예약번호가 겹친다** — 번호를 마지막 행 번호로 만들기 때문이다. 행이 하나일 때
`R-2607-0001` 이 나갔는데 그 행을 지우면 다음 신청도 `R-2607-0001` 을 받는다.
이미 알려준 번호와 같아지면 취소할 때 엉뚱한 예약을 건드린다. 기록도 사라진다.

**상태는 드롭다운으로만.** `승인 ` 처럼 뒤에 공백이 붙거나 `승인함` 같이 적으면
그 예약은 화면에서 조용히 사라진다.

**시트 공유는 담당 선생님까지만.** 웹앱이 소유자 권한으로 도니까 학생에게 시트를
공유할 이유가 없다.

**대기 중인 신청은 남의 신청을 막지 않는다.** 겹쳐서 신청이 들어올 수 있고, 그때는
하나만 `승인` 하고 나머지를 `반려` 한다. 이미 승인된 시간과 겹치는 신청은 스크립트가
접수 단계에서 거절한다.

**코드를 고친 뒤에는 반드시 다시 배포한다.** *배포 → 배포 관리 → 연필 → 버전 새로
만들기*. 저장만 하면 웹앱에는 반영되지 않는다.

**한 학년도가 끝나면 시트를 새로 만든다.** 수천 행이 되면 조회가 느려진다.
